## What this repo is

The **CipherTrust Terraform Provider** lets users manage Thales CipherTrust Manager (CM)
resources using Infrastructure-as-Code. It translates `terraform plan/apply/destroy` calls
into CipherTrust Manager REST API calls. It is published at
`github.com/ThalesGroup/terraform-provider-ciphertrust` on branch `1.0.1`.

CipherTrust Manager (CM) is Thales's enterprise key-management platform. Provider
sub-areas: **CM** (core platform), **CCKM** (cloud key-management — AWS/Azure/GCP/OCI),
**CTE** (CipherTrust Transparent Encryption — file/volume encryption policies).

## ⚠ Critical project constraint — TFIN-174

**Empty `Read()` is the root cause of ALL drift issues.** Every resource's `Read` method
currently returns without calling the CM API, so Terraform never reconciles state against
reality. This masks all other bugs (immutable-field violations, case mismatches, tag swaps).

**Fix order is mandatory:**
1. Fix `Read()` first (TFIN-174) — once API is called during plan, all drift becomes visible.
2. Fix `RequiresReplace` on immutable fields (TFIN-183, TFIN-179, TFIN-181).
3. Fix case normalization and JSON tag issues (TFIN-195, TFIN-194).

If your task is NOT TFIN-174, do not implement a proper `Read()` as a side-effect — it will
surface drift before the immutable-field fixes are in and will confuse users. Leave `Read()`
empty unless the ticket specifically asks you to fix it.

# Implementation Plan: TFIN-293

## Overview

Implement proper `Read()` methods for 5 CM resources whose Read functions are currently empty stubs. Each Read must call the CM appliance API, handle 404 (remove from state), reconcile drift into state, and propagate other errors as diagnostics.

**TFIN-174 exception:** The ticket does not explicitly cite TFIN-174. Treat the override as an open question — confirm with the tech lead before merge that the "empty Read" rule is waived for exactly these 5 resources. The ticket's expected behaviour is incompatible with an empty Read, so the override is implicit but should be recorded in the PR description.

## Files to Modify

### 1. `internal/provider/cm/resource_cm_key.go`
- Replace stub `Read()` on `resourceCMKey`.
- Client method: `client.GetById(ctx, state.ID.ValueString(), URL_CM_KEY)` (pattern used in `Create`/`Update` of this same file). Endpoint: `/vault/keys2/{id}`.
- 404 → `resp.State.RemoveResource(ctx)`; other errors → `resp.Diagnostics.AddError`.
- **Write-only fields to copy from prior state into refreshed model before `Set`:** `material`, `wrapping_method`, `wrapping_key_name`, `wrapping_encryption_algo`, `wrapping_hash_algo`, `password`, `import_key_material`, `id_size`, `template_id`, `xts`. Any field absent from the GET response payload must be preserved verbatim.

### 2. `internal/provider/cm/resource_cm_group.go`
- The Terraform `id` for this resource stores the group **name** (set in `Create` from the `name` attribute; CM groups have no UUID). Confirm by inspecting the existing `Create()` in this file before coding.
- Client method: `client.GetById(ctx, state.ID.ValueString(), URL_CM_GROUP)`. Endpoint: `/usermgmt/groups/{name}`.
- **Write-only fields to preserve:** none (all attributes — `name`, `description`, `users`, `client_id`, `app_metadata`, `user_metadata` — are returned by GET).

### 3. `internal/provider/cm/resource_cm_ssh_key.go`
- Client method: `client.GetById(ctx, state.ID.ValueString(), URL_CM_SSH_KEY)`. Endpoint: `/auth/ssh-keys/{id}`.
- **Write-only fields to preserve:** `key` (the public-key body is sometimes returned truncated/normalised; preserve user input to avoid diff churn).

### 4. `internal/provider/cm/resource_cm_user_pwd_change.go`
- This is an action-style resource. State `id` holds the username (set in `Create`).
- Client method: `client.GetById(ctx, state.Username.ValueString(), URL_CM_USER)`. Endpoint: `/usermgmt/users/{username}`.
- On 404: `RemoveResource`. On success: do not reconcile any field — copy `username`, `password`, `new_password`, `auth_domain` from prior state and `Set` unchanged. The resource has no observable drift; Read only verifies user existence.

### 5. `internal/provider/cm/resource_cm_reg_token.go`
- Client method: `client.GetById(ctx, state.ID.ValueString(), URL_CM_REG_TOKEN)`. Endpoint: `/client-management/regtokens/{id}`.
- **Write-only fields to preserve:** `ca_id`, `cert_duration`, `label` (any not echoed by GET).
