## What this repo is

The **CipherTrust Terraform Provider** lets users manage Thales CipherTrust Manager (CM)
resources using Infrastructure-as-Code. It translates `terraform plan/apply/destroy` calls
into CipherTrust Manager REST API calls. It is published at
`github.com/ThalesGroup/terraform-provider-ciphertrust` on branch `1.0.1`.

CipherTrust Manager (CM) is Thales's enterprise key-management platform. Provider
sub-areas: **CM** (core platform), **CCKM** (cloud key-management — AWS/Azure/GCP/OCI),
**CTE** (CipherTrust Transparent Encryption — file/volume encryption policies).

## ⚠ Critical project constraint — TFIN-174

**Empty `Read()` is the root cause of ALL drift issues.** Every resource's `Read` method
currently returns without calling the CM API, so Terraform never reconciles state against
reality. This masks all other bugs (immutable-field violations, case mismatches, tag swaps).

**Fix order is mandatory:**
1. Fix `Read()` first (TFIN-174) — once API is called during plan, all drift becomes visible.
2. Fix `RequiresReplace` on immutable fields (TFIN-183, TFIN-179, TFIN-181).
3. Fix case normalization and JSON tag issues (TFIN-195, TFIN-194).

If your task is NOT TFIN-174, do not implement a proper `Read()` as a side-effect — it will
surface drift before the immutable-field fixes are in and will confuse users. Leave `Read()`
empty unless the ticket specifically asks you to fix it.

# TFIN-167 Implementation Plan: Implement Read() for 5 CM Core Resources

## Overview
Five CM resources have empty/stub `Read()` methods. This ticket explicitly authorizes implementing real Read() logic for these resources, overriding the default TFIN-174 "Read stays empty" rule. Each Read() must call the CM API, refresh state from the response, and remove the resource from state on 404.

## Pattern to Follow
Primary reference (same package, closest analog, cited by the ticket):
**`internal/provider/cm/resource_cm_user.go`** — its `Read` method demonstrates: prior-state retrieval via `req.State.Get`, client GET-by-ID, 404 detection → `resp.State.RemoveResource(ctx)` with a `Warning` diagnostic, response→model mapping, and `resp.State.Set`.

Secondary references: **`internal/provider/scheduler/resource_scheduler.go`** (cited by ticket) and **`internal/provider/cckm/aws/resource_aws_policy_template.go`** (simple shape).

404 helper: **`common.IsNotFoundError(err)`** defined in **`internal/provider/common/errors.go`** — same helper used by `resource_cm_user.go` and CCKM resources. Do not introduce a new helper.

## Files to MODIFY

Replace the empty/stub `Read` only. Do NOT change schemas, attributes, Required/Optional/Computed flags, RequiresReplace, Create, Update, or Delete.

1. **`internal/provider/cm/resource_cm_key.go`**
   - Model struct: `CMKeyTFSDK` (already declared in this file).
   - Client call: `client.GetById(ctx, id, common.URL_CM_KEY)` (same call used by Create's post-create refresh).
   - Refresh attributes: `id`, `name`, `algorithm`, `size`, `usage_mask`, `unexportable`, `undeletable`, `meta`, `owner_id`, `version`, `state`, `activation_date`, `deactivation_date`, `archive_date`, `destroy_date`, `compromise_date`, `compromise_occurrence_date`, `process_start_date`, `protect_stop_date`, `revocation_reason`, `revocation_message`.
   - **Preserve from prior state** (write-only / not returned by GET): `material`, `wrapping_method`, `wrapping_key_name`, `wrapping_hashing_algorithm`, `wrapping_encryption_algo`, `password`, `id_size`, `template_id`.
   - On 404 (`common.IsNotFoundError`) → `resp.State.RemoveResource(ctx)` + `resp.Diagnostics.AddWarning(...)`.

2. **`internal/provider/cm/resource_cm_group.go`**
   - Model struct: `CMGroupTFSDK`.
   - Client call: `client.GetById(ctx, name, common.URL_CM_GROUP)` — group is keyed by name.
   - Refresh attributes: `name`, `description`, `users`, `app_metadata`, `client_metadata`, `user_metadata`, `created_at`, `updated_at`.
   - On 404 → `RemoveResource` + warning.

3. **`internal/provider/cm/resource_cm_ssh_key.go`**
   - Model struct: `CMSSHKeyTFSDK`.
   - Client call: `client.GetById(ctx, id, common.URL_CM_SSH_KEY)`.
   - Refresh attributes: `id`, `key`, `created_at`.
   - **Preserve from prior state** if API omits: `key` (public key body may not be re-emitted by the GET).
   - On 404 → `RemoveResource` + warning.

4. **`internal/provider/cm/resource_cm_user_pwd_change.go`**
   - This resource performs a one-shot password change; the ticket lists it among the 5. Implement a real Read that calls **`client.GetById(ctx, username, common.URL_CM_USER)`** to confirm the user still exists.
   - Refresh attributes: `username` only (do NOT touch `password` or `new_password` — both write-only/sensitive, preserved from prior state).
   - On 404 (user deleted) → `RemoveResource` + warning. This satisfies the ticket's deletion-detection requirement without exposing password drift.

5. **`internal/provider/cm/resource_cm_reg_token.go`**
   - Model struct: `CMRegTokenTFSDK`.
   - Client call: `client.GetById(ctx, id, common.URL_CM_REG_TOKEN)`.
   - Refresh attributes: `id`, `cert_duration`, `name_prefix`, `ca_id`, `label`, `lifetime`, `max_clients`, `created_at`.
   - **Preserve from prior state**: `token` (sensitive, not returned by GET).
   - On 404 → `RemoveResource` + warning.

## Constraints
- No schema changes; no new attributes; no flag changes.
- Sensitive / write-only attributes must be copied from prior state into the refreshed model before `resp.State.Set`.
- 404 diagnostic must be `Warning` (matches `resource_cm_user.go`).
