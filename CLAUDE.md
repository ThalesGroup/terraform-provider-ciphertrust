## What this repo is

The **CipherTrust Terraform Provider** lets users manage Thales CipherTrust Manager (CM)
resources using Infrastructure-as-Code. It translates `terraform plan/apply/destroy` calls
into CipherTrust Manager REST API calls. It is published at
`github.com/ThalesGroup/terraform-provider-ciphertrust` on branch `1.0.1`.

CipherTrust Manager (CM) is Thales's enterprise key-management platform. Provider
sub-areas: **CM** (core platform), **CCKM** (cloud key-management — AWS/Azure/GCP/OCI),
**CTE** (CipherTrust Transparent Encryption — file/volume encryption policies).

## ⚠ Critical project constraint — TFIN-174

**Empty `Read()` is the root cause of ALL drift issues.** Every resource's `Read` method
currently returns without calling the CM API, so Terraform never reconciles state against
reality. This masks all other bugs (immutable-field violations, case mismatches, tag swaps).

**Fix order is mandatory:**
1. Fix `Read()` first (TFIN-174) — once API is called during plan, all drift becomes visible.
2. Fix `RequiresReplace` on immutable fields (TFIN-183, TFIN-179, TFIN-181).
3. Fix case normalization and JSON tag issues (TFIN-195, TFIN-194).

If your task is NOT TFIN-174, do not implement a proper `Read()` as a side-effect — it will
surface drift before the immutable-field fixes are in and will confuse users. Leave `Read()`
empty unless the ticket specifically asks you to fix it.

# Implementation Plan: TFIN-292 — Implement Read() for 5 CM Core Resources

## Overview
The ticket explicitly mandates real `Read()` implementations for 5 CM resources. This is a documented exception to TFIN-174 (which keeps `Read()` empty by default). Each new `Read()` must call CM, handle 404 by removing the resource from state, refresh every schema attribute, and persist via `resp.State.Set`.

## Reference Patterns (verified paths)
- **Primary**: `internal/provider/cckm/aws/resource_cckm_aws_key.go` — see its `Read` method: state read → `r.client.GetById(ctx, id, common.URLAwsKey, &response)` → `if err != nil { if strings.Contains(err.Error(), common.ErrorCodeNotFound) { resp.State.RemoveResource(ctx); return } ... }` → field mapping → `resp.State.Set`.
- **Secondary**: `internal/provider/cm/resource_cm_user.go` (`Read`) and `internal/provider/scheduler/resource_scheduler.go` (`Read`) — same idiom, simpler models.
- **Client method to use**: `r.client.GetById(ctx, id, <URL constant>, &payload)` defined in `internal/provider/common/client.go`. The 404 sentinel is `common.ErrorCodeNotFound` (do NOT inline `"404"` strings).

## Files to MODIFY

### 1. `internal/provider/cm/resource_cm_key.go`
- Endpoint constant: `common.URLCMKey` (already used by `Create` — confirm by grepping `client.PostData` / `client.GetById` calls in this file).
- Replace empty `Read()` with: read prior state into `tfsdkCMKeyModel`, call `r.client.GetById(ctx, state.ID.ValueString(), common.URLCMKey, &jsonData)`, handle 404 via `common.ErrorCodeNotFound`, then refresh exactly these schema attributes: `id`, `name`, `algorithm`, `size`, `usage_mask`, `labels`, `meta`, `version`, `unexportable`, `undeletable`, `state`, `description`, `owner_id`, `aliases`, `activation_date`, `deactivation_date`, `archive_date`, `process_start_date`, `protect_stop_date`, `key_id`, `uri`, `uuid`. Sensitive material (`material`, `wrap_key_name`) is write-only — preserve from prior state via conditional assignment (only overwrite if API returns a non-empty value).

### 2. `internal/provider/cm/resource_cm_group.go`
- Endpoint constant: `common.URLCMGroup` (id segment is group `name`).
- Refresh: `name`, `description`, `users` (list), `app_metadata`, `client_metadata`, `created_at`, `updated_at`. No sensitive fields.

### 3. `internal/provider/cm/resource_cm_ssh_key.go`
- Endpoint constant: `common.URLCMSSHKey` as used in this file's `Create`.
- Refresh: `id`, `key`, `user_id`, `created_at`. The `key` body is returned by CM; map directly. No sensitive preservation needed.

### 4. `internal/provider/cm/resource_cm_user_pwd_change.go`
- **Per critic point 6**: ticket lists this resource with no exemption. Implement a real `Read()` that calls `GET /usermgmt/users/{user_id}` (`common.URLCMUser`) using the `user_id` stored in state, refreshes `username`, `user_id`, `email`, `full_name`, `last_login` if present. Do NOT refresh or store any password field. On 404, remove from state. This satisfies the ticket's drift-detection requirement (deletion of the user is detected) without exposing secrets.

### 5. `internal/provider/cm/resource_cm_reg_token.go`
- Endpoint constant: `common.URLCMRegToken`.
- Refresh: `id`, `name_prefix`, `cert_duration`, `lifetime`, `max_clients`, `ca_id`, `label`, `created_at`. The `token` attribute is `Computed`+`Sensitive`; preserve prior state value if API omits it (CM may not return token after creation), else overwrite.

## Schema Changes
**None.** All attributes referenced above already exist in each resource's `Schema()`.

## 404 Handling — single mandated idiom
`if err != nil { if strings.Contains(err.Error(), common.ErrorCodeNotFound) { tflog.Warn(ctx, "Resource not found on CM, removing from state"); resp.State.RemoveResource(ctx); return }; resp.Diagnostics.AddError(...); return }`. No alternative forms.

## Sensitive-Field Preservation Rule
For each Computed+Sensitive or write-only attribute (`material`, `wrap_key_name` in cm_key; `token` in cm_reg_token): assign API value only if non-empty/non-null; otherwise copy from prior state. No password fields are read or written in cm_user_pwd_change.
