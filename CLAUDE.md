## What this repo is

The **CipherTrust Terraform Provider** lets users manage Thales CipherTrust Manager (CM)
resources using Infrastructure-as-Code. It translates `terraform plan/apply/destroy` calls
into CipherTrust Manager REST API calls. It is published at
`github.com/ThalesGroup/terraform-provider-ciphertrust` on branch `1.0.1`.

CipherTrust Manager (CM) is Thales's enterprise key-management platform. Provider
sub-areas: **CM** (core platform), **CCKM** (cloud key-management — AWS/Azure/GCP/OCI),
**CTE** (CipherTrust Transparent Encryption — file/volume encryption policies).

## ⚠ Critical project constraint — TFIN-174

**Empty `Read()` is the root cause of ALL drift issues.** Every resource's `Read` method
currently returns without calling the CM API, so Terraform never reconciles state against
reality. This masks all other bugs (immutable-field violations, case mismatches, tag swaps).

**Fix order is mandatory:**
1. Fix `Read()` first (TFIN-174) — once API is called during plan, all drift becomes visible.
2. Fix `RequiresReplace` on immutable fields (TFIN-183, TFIN-179, TFIN-181).
3. Fix case normalization and JSON tag issues (TFIN-195, TFIN-194).

If your task is NOT TFIN-174, do not implement a proper `Read()` as a side-effect — it will
surface drift before the immutable-field fixes are in and will confuse users. Leave `Read()`
empty unless the ticket specifically asks you to fix it.

# Implementation Plan: TFIN-288 — Implement Read Method for Terraform Resource User

## Context & Constraint Check

This ticket **explicitly asks** for the `Read()` method to be implemented for the `user` resource. Per TFIN-174, Read methods are currently stubbed empty across the provider. This ticket is the explicit exception for the user resource — proceed with a real implementation, but scope it strictly to `resource_user` and do not touch other resources' Read methods.

Before coding, confirm with the team that TFIN-174's drift-handling concerns (e.g. how to treat 404s, computed-field round-tripping) have a documented resolution for user. If not, surface this as a blocker on the ticket.

## Files to Modify

### 1. `internal/provider/cm/resource_user.go` (primary change)
This is the file containing the `User` resource type and its currently-empty `Read()` method. Modify the `Read()` method to:

- Read prior state into the resource model struct via `req.State.Get(ctx, &state)`; return on diagnostic errors.
- Extract the user ID from state (the `id` attribute set during Create).
- Call the CM client's "get user by ID" endpoint. Use the same client field (`r.client`) and HTTP/SDK call conventions as Create/Update in the same file.
- On HTTP 404 (user deleted out-of-band): call `resp.State.RemoveResource(ctx)` and return without error so Terraform plans a recreate.
- On other errors: append an error diagnostic with the endpoint and ID context, then return.
- Map the API response onto the state model. Ensure every Computed and Optional+Computed attribute defined in the schema is populated, including: `user_id`, `username`, `email`, `name`, `nickname`, `logins_count`, `last_login`, `created_at`, `updated_at`, `failed_logins_count`, `account_lockout_at`, `enable_cert_auth`, `certificate_subject_dn`, plus any nested `user_metadata` / `login_flags` objects.
- Do **not** overwrite the `password` attribute from the API (it is write-only); preserve the prior state value.
- Persist final state via `resp.State.Set(ctx, &state)`.

### 2. `internal/provider/cm/schema_cm.go` (verify only)
Confirm the user schema declares all returned fields as Computed or Optional+Computed so they can be safely refreshed. If any returned field is currently Optional-only (not Computed), mark it Optional+Computed. Do not change Required fields' computed status. Note any field that needs schema changes here in the PR description.

## Pattern to Follow

Use **`internal/provider/connections/resource_scp_connection.go`** as the structural pattern. Specifically mirror its `Read()` method shape: state-get → ID extraction → API call → 404 handling → response-to-model mapping → state-set. The companion **`internal/provider/connections/data_source_scp_connection.go`** shows the response-to-model mapping helper style and is useful if you choose to factor mapping into a shared helper.

Also reference `internal/provider/cm/resource_interface.go` to confirm the `Read()` signature matches the framework's `resource.Resource` interface contract used provider-wide.

- **Scope discipline:** do not implement Read for any other resource — TFIN-174 still governs them.
- **Sensitive fields:** ensure no secret values are logged in error diagnostics.
