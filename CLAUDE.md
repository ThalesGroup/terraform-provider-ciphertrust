## What this repo is

The **CipherTrust Terraform Provider** lets users manage Thales CipherTrust Manager (CM)
resources using Infrastructure-as-Code. It translates `terraform plan/apply/destroy` calls
into CipherTrust Manager REST API calls. It is published at
`github.com/ThalesGroup/terraform-provider-ciphertrust` on branch `1.0.1`.

CipherTrust Manager (CM) is Thales's enterprise key-management platform. Provider
sub-areas: **CM** (core platform), **CCKM** (cloud key-management — AWS/Azure/GCP/OCI),
**CTE** (CipherTrust Transparent Encryption — file/volume encryption policies).

## ⚠ Critical project constraint — TFIN-174

**Empty `Read()` is the root cause of ALL drift issues.** Every resource's `Read` method
currently returns without calling the CM API, so Terraform never reconciles state against
reality. This masks all other bugs (immutable-field violations, case mismatches, tag swaps).

**Fix order is mandatory:**
1. Fix `Read()` first (TFIN-174) — once API is called during plan, all drift becomes visible.
2. Fix `RequiresReplace` on immutable fields (TFIN-183, TFIN-179, TFIN-181).
3. Fix case normalization and JSON tag issues (TFIN-195, TFIN-194).

If your task is NOT TFIN-174, do not implement a proper `Read()` as a side-effect — it will
surface drift before the immutable-field fixes are in and will confuse users. Leave `Read()`
empty unless the ticket specifically asks you to fix it.

# Implementation Plan: TFIN-289 — Implement Read Method for `cm_key` Resource

## Scope & Interpretation

This ticket **explicitly asks** for the Read method on the CM key resource. Per the TFIN-174 constraint, this is one of the rare cases where implementing a real `Read()` is sanctioned. This plan covers `resource_cm_key.go` only; other resources remain stub-Read until TFIN-174 is addressed separately.

## Files to MODIFY

### 1. `internal/provider/cm/resource_cm_key.go` (primary change)

Replace the currently empty `Read(ctx, req, resp)` method with a real implementation that:

- Reads the prior state into the resource's state model struct (the same struct already used by `Create`/`Update` in this file).
- Extracts the key identifier from state — use the `id` attribute (CipherTrust Manager key UUID) as the canonical lookup. Do **not** rely on `name` or `version`, since those can change.
- Calls the CM API via the existing HTTP helper in `internal/provider/common/requests.go`. Use the `GET /vault/keys2/{id}` endpoint. Follow the request-construction and error-handling pattern from `resource_azure_connection.go`'s Read (most complete reference) and `resource_scp_connection.go`'s Read.
- On HTTP 404 (key deleted out-of-band): call `resp.State.RemoveResource(ctx)` and return without error — this is required for correct Terraform drift handling.
- On other non-2xx responses: append a diagnostic error with the response body and return.
- On success: decode the JSON response into the API response struct (reuse or add alongside the existing request struct in the same file; mirror the field layout used in `data_source_scp_connection.go`).
- Map API response fields back onto the state model. Cover at minimum: `id`, `name`, `algorithm`, `size`, `usage_mask`, `unexportable`, `undeletable`, `state`, `version`, `meta`, `labels`, `activation_date`, `deactivation_date`, `archive_date`, `destroy_date`, `process_start_date`, `protect_stop_date`, `object_type`, `curve_id`, `key_id`, `default_iv`. Match the attribute list in `schema_cm.go`.
- For nested/object attributes (e.g. `meta`, `labels`), use the same conversion helpers (`types.MapValueFrom`, `types.ObjectValueFrom`) already used in the Create path of this file. Do not invent new helpers.
- Persist via `resp.Diagnostics.Append(resp.State.Set(ctx, &state)...)`.

## Constraints & Risks

- **Sensitive/write-only fields:** Do not overwrite `material` or any password-like field from the API response if the API returns a masked value — leave the state value untouched to avoid spurious diffs. Check `schema_cm.go` for any attribute marked `Sensitive`.
- **Computed-only fields** (e.g. `key_id`, `uri`, timestamps generated server-side) must be set from the response even if absent from prior state.
- **Null vs. empty handling:** preserve Terraform null semantics for optional fields the API omits — do not coerce to empty strings.
- **No Update/Create/Delete changes** in this ticket.
