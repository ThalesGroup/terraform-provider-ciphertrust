## What this repo is

The **CipherTrust Terraform Provider** lets users manage Thales CipherTrust Manager (CM)
resources using Infrastructure-as-Code. It translates `terraform plan/apply/destroy` calls
into CipherTrust Manager REST API calls. It is published at
`github.com/ThalesGroup/terraform-provider-ciphertrust` on branch `1.0.1`.

CipherTrust Manager (CM) is Thales's enterprise key-management platform. Provider
sub-areas: **CM** (core platform), **CCKM** (cloud key-management — AWS/Azure/GCP/OCI),
**CTE** (CipherTrust Transparent Encryption — file/volume encryption policies).

## ⚠ Critical project constraint — TFIN-174

**Empty `Read()` is the root cause of ALL drift issues.** Every resource's `Read` method
currently returns without calling the CM API, so Terraform never reconciles state against
reality. This masks all other bugs (immutable-field violations, case mismatches, tag swaps).

**Fix order is mandatory:**
1. Fix `Read()` first (TFIN-174) — once API is called during plan, all drift becomes visible.
2. Fix `RequiresReplace` on immutable fields (TFIN-183, TFIN-179, TFIN-181).
3. Fix case normalization and JSON tag issues (TFIN-195, TFIN-194).

If your task is NOT TFIN-174, do not implement a proper `Read()` as a side-effect — it will
surface drift before the immutable-field fixes are in and will confuse users. Leave `Read()`
empty unless the ticket specifically asks you to fix it.

# Implementation Plan: TFIN-167 (Revised)

## Overview
Implement real `Read()` methods for 5 CM core resources whose Read is currently empty. Each Read must call the CM API, populate state from the response, and remove the resource from state on 404 so Terraform detects out-of-band deletion and drift.

This ticket explicitly overrides the TFIN-174 "leave Read empty" constraint **for these 5 resources only**. All other resources remain untouched.

## Canonical Pattern
Reference: `(r *resourceCCKMAWSKey) Read` in `internal/provider/cckm/aws/resource_aws_key.go`. It demonstrates: state read → API GET by ID → 404 → `resp.State.RemoveResource(ctx)` → otherwise hydrate model → `resp.State.Set`.

Secondary references for the same pattern: `(r *resourceCMUser) Read` in `internal/provider/cm/resource_cm_user.go` and `(r *resourceScheduler) Read` in `internal/provider/scheduler/resource_scheduler.go`.

## 404 Detection Idiom
The codebase convention (see top of `internal/provider/cckm/aws/resource_aws_key.go` Read) is a substring match on `"NotFound"` / `"not found"` returned by the common client wrapper in `internal/provider/common/client.go` (`GetByID`/`GetByURL`). Use the existing helper `common.IsNotFoundError(err)` if present in `internal/provider/common/errors.go`; if it does not exist, add it there as the single source of truth and migrate all 5 resources to it. All implementers must call this helper — no inline string matching.

## Files to MODIFY

### 1. `internal/provider/cm/resource_cm_key.go`
- Replace empty `Read`. Read prior state, call `client.GetByID(ctx, id, URL_CM_KEY)` (the same call used in `(r *resourceCMKey) Update`).
- Extract API-payload→state mapping currently inline in `Create` into a new package-private helper `mapCMKeyResponseToState` in the same file; call it from `Create`, `Update`, and `Read`.
- Sensitive/write-only fields to copy from prior state (not returned by GET): `material`, `wrapping_key_name`, `password_link_config`, `import_key_material`. List comes from the schema in `internal/provider/cm/resource_cm_key.go`.

### 2. `internal/provider/cm/resource_cm_group.go`
- Group is keyed by `name`. Use `client.GetByID(ctx, name, URL_CM_GROUP)` matching the path used by `Update`/`Delete`.
- Extract `mapCMGroupResponseToState` helper. No sensitive fields; all attributes are returned by GET.

### 3. `internal/provider/cm/resource_cm_ssh_key.go`
- Use `client.GetByID(ctx, id, URL_CM_SSH_KEY)` (same endpoint as `Delete`).
- Extract `mapCMSSHKeyResponseToState`.
- Sensitive/write-only field to preserve from prior state: `key` (raw public-key body — write-only on most CM builds).

### 4. `internal/provider/cm/resource_cm_user_pwd_change.go`
- **Decision (confirm with ticket owner before merge; note in TFIN-167):** This resource models a one-shot password-change action and has no resource GET endpoint on CM. Implementing real drift detection is not possible without a server-side handle.
- Read implementation: call `req.State.Get(ctx, &state)` then `resp.State.Set(ctx, &state)` to satisfy the framework contract. Add a `// TFIN-167:` comment block explaining the exemption and linking the ticket.
- If the ticket owner rejects the no-op, fallback plan: call `client.GetByID(ctx, username, URL_CM_USER)` to verify the target user still exists; on 404 remove from state. This requires no schema change.

### 5. `internal/provider/cm/resource_cm_reg_token.go`
- Use `client.GetByID(ctx, id, URL_CM_REG_TOKEN)` (same endpoint as `Delete`).
- Extract `mapCMRegTokenResponseToState`.
- Sensitive/write-only fields to preserve from prior state: `token` (returned only at create), `ca_id` if absent in GET response, and `cert_duration` for builds where GET omits it.

## Schema Changes
None. No new attributes; behavior-only fix. No `RequiresReplace` concerns.

## Constraints
- All 404 detection routed through `common.IsNotFoundError`.
- Sensitive/write-only fields enumerated above must be copied from prior state before `resp.State.Set` to avoid spurious diffs.
- Per TFIN-174, no other resource's Read is touched.
