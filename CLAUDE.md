## What this repo is

The **CipherTrust Terraform Provider** lets users manage Thales CipherTrust Manager (CM)
resources using Infrastructure-as-Code. It translates `terraform plan/apply/destroy` calls
into CipherTrust Manager REST API calls. It is published at
`github.com/ThalesGroup/terraform-provider-ciphertrust` on branch `1.0.1`.

CipherTrust Manager (CM) is Thales's enterprise key-management platform. Provider
sub-areas: **CM** (core platform), **CCKM** (cloud key-management — AWS/Azure/GCP/OCI),
**CTE** (CipherTrust Transparent Encryption — file/volume encryption policies).

## ⚠ Critical project constraint — TFIN-174

**Empty `Read()` is the root cause of ALL drift issues.** Every resource's `Read` method
currently returns without calling the CM API, so Terraform never reconciles state against
reality. This masks all other bugs (immutable-field violations, case mismatches, tag swaps).

**Fix order is mandatory:**
1. Fix `Read()` first (TFIN-174) — once API is called during plan, all drift becomes visible.
2. Fix `RequiresReplace` on immutable fields (TFIN-183, TFIN-179, TFIN-181).
3. Fix case normalization and JSON tag issues (TFIN-195, TFIN-194).

If your task is NOT TFIN-174, do not implement a proper `Read()` as a side-effect — it will
surface drift before the immutable-field fixes are in and will confuse users. Leave `Read()`
empty unless the ticket specifically asks you to fix it.

# TFIN-167 Implementation Plan: Fix Empty Read() for 5 CM Resources

## Overview
The ticket explicitly mandates real `Read()` implementations to detect out-of-band deletion and drift, quoting: *"The Terraform Plugin Framework contract requires Read() to call the remote API … If the resource is not found (404), it must call resp.State.RemoveResource(ctx). None of this is implemented for the 5 affected resources."* This language directly authorizes overriding the standing TFIN-174 "empty Read" rule **for these 5 resources only**. No other resource is touched.

## Reference Pattern
Primary pattern: **`internal/provider/cm/resource_cm_user.go`** — `func (r *resourceCMUser) Read(ctx context.Context, req resource.ReadRequest, resp *resource.ReadResponse)`. Chosen over `cckm/aws/resource_aws_key.go` because the ticket names `ciphertrust_cm_user` as a reference and it lives in the same subpackage, uses the same client wrapper, and applies the same model shape conventions as the 5 targets.

Secondary pattern: **`internal/provider/cm/resource_cm_scheduler.go`** Read — for the diagnostic-warning text on state removal.

The 404 detection idiom used in both: an `errors.Is(err, common.ErrResourceNotFound)` check (or the equivalent typed-error helper exported by `internal/provider/common`). The exact symbol must be reused verbatim from `resource_cm_user.go` Read.

## Read() Behavior Contract
- Prior state via `req.State.Get(ctx, &state)`; abort on diag errors.
- 404 (`errors.Is(err, common.ErrResourceNotFound)`) → warning "Resource removed from state" (text from `resource_cm_scheduler.go`) + `resp.State.RemoveResource(ctx)`; return.
- Other errors → `resp.Diagnostics.AddError(...)`; return.
- Success → map response into model, copy preserved fields from `state`, then `resp.State.Set(ctx, &model)`.
